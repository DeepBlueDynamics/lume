# Luxir vs. Lume Benchmark: BEIR SciFact and TREC-COVID

This benchmark compares **Luxir** (v0.1.0) and **Lume** (v0.12.2) on the BEIR test splits of SciFact and TREC-COVID. Both systems were tested on identical host hardware using Docker Linux containers under strict parity constraints (`--cpus 8 --memory 8g`, loopback binding only, shared local Shivvr embeddings).

---

## 1. Test Environment & Fairness Setup

### Hardware & Container Constraints
- **Host**: 24-core x86_64 host running Windows 11 and Docker Desktop 29.4.0 (WSL2 backend).
- **Container Limits**: Both engines run in separate Linux containers constrained to `--cpus 8 --memory 8g`.
- **Storage Subsystem**: Dedicated Linux Docker named volumes (`luxir-bench-data` for Luxir, mounted at `/var/lib/luxir_data`, and a corresponding Linux volume for Lume) are used for index storage. Neither engine uses Windows host bind mounts for its index directory, eliminating VirtioFS/9p translation overhead.
- **Network & Security**: All engine ports are published exclusively on `127.0.0.1` (`9400` for Luxir HTTP/JSON, `8080/8085` for Lume/Shivvr).
- **Embedding Alignment**: Hybrid runs for both engines use identical 768-dimensional dense vectors generated by the local Shivvr daemon (`gtr-t5-base`, cosine metric) served at `http://host.docker.internal:8085/embed`.

### Software Under Test
- **Luxir**:
  - Version: `0.1.0 (x86-64-v3, AVX2)`
  - Distribution: Prebuilt Linux x86_64 binary (`https://luxir.org/download/luxir-v0.1.0-linux-x86_64-v3.tar.gz`)
  - Checksum (SHA-256): `5bcfe74159b5abba9bbafffeb6a224483cc8f8f37ad85d76568627555b3a434f`
  - Container Command:

  - Schema Configuration: `text` configured with parent `_t` (Unicode-word tokenizer, NFKC case/accent folding, English possessive removal, KStem stemming, BM25 scoring). Hybrid mode adds `embedding_v: {type: "vector", dims: 768, metric: "cosine"}`.
  - Query Interface:

## 2. Benchmark Contract & Measurement Protocol

The evaluation is managed through a shared test harness (`prepare.py` and `score.py`):
1. **Datasets**:
   - **SciFact**: 5,183 documents, 300 test queries, 339 qrels.
   - **TREC-COVID**: 171,332 documents, 50 test queries, 66,336 qrels.
2. **Scoring Conventions**:
   - **nDCG@10**: Linear relevance gain, log2 discount, depth 10.
   - **Recall@100**: Positive relevance judgments (grade > 0), depth 100.
   - **MRR@10**: First positive relevance judgment, depth 10.
   - **Macro-averaging**: Unretrieved queries receive zero score across all quality metrics.
3. **Latency Protocol**:
   - One complete warmup pass over all test queries.
   - Three timed passes sequentially recording per-query elapsed time in milliseconds via high-resolution monotonic timer (`time.perf_counter()`).
   - Per-query latency is the median of the three passes; report percentiles (p50, p95, p99) use linear interpolation.
4. **Throughput Protocol**:
   - 8 concurrent worker clients querying continuously for 60 seconds against a warm server.
   - Measured requests, errors, and achieved QPS.
5. **Serialization Protocol**:
   - Zero concurrent host load: only one engine builds or times on the host at any given time using explicit `START`/`DONE` locks.

### Indexing Observations
- **Throughput**: Luxir indexed the 171,332 TREC-COVID documents in 7.10 seconds (>24,100 docs/sec) in BM25 mode on the named volume. For SciFact, full-text indexing completed in 0.31 seconds (~16,700 docs/sec).
- **Index Compression**: Luxir's committed BM25 index on disk is 8.27 MB for SciFact (vs. 57.80 MB for Lume, a 7.0x smaller footprint) and 182.81 MB for TREC-COVID.
- **Memory Efficiency**: Peak RSS during full TREC-COVID BM25 indexing remained under 103 MB, settling to 36.49 MB idle memory after flush and segment commit.

## 5. Retrieval Quality Analysis

### SciFact (Biomedical Fact Verification)
- **BM25 Baseline**: Luxir achieved **0.6793 nDCG@10**, **0.9213 Recall@100**, and **0.6445 MRR@10**.
- **Dense Vector Hybrid (RRF k=60)**: Fusing BM25 with Shivvr `gtr-t5-base` cosine embeddings yielded notable gains across every quality metric:
  - **nDCG@10**: +0.0150 (+2.2%) to **0.6943**
  - **Recall@100**: +0.0350 (+3.8%) to **0.9563**
  - **MRR@10**: +0.0192 (+3.0%) to **0.6637**

### TREC-COVID (Broad Pandemic Literature Search)
- **BM25 Baseline**: Luxir achieved **0.6052 nDCG@10** and **0.8758 MRR@10**, demonstrating high precision at rank 10 on a large collection of medical abstracts.

## 6. Architectural Differences & Fairness Caveats

1. **Resident Daemon vs. Per-Query Deserialization**:
   - **Luxir** operates as a native C++ long-running search service (`luxir` daemon) maintaining resident segment metadata and mmap page caches.
   - **Lume v0.12.2 Released** deserializes index JSON files per MCP request (`LoadedIndex::open` in `src/agent.rs`), incurring per-query file I/O and JSON parsing overhead. The comparison distinguishes released baseline performance from resident in-memory performance.
2. **Storage Subsystem Parity**:
   - Initial test exploration mounted indexes through the Windows host directory. To ensure full fairness, all official runs were re-executed using native Docker Linux named volumes (`luxir-bench-data`), isolating both engines from host filesystem translation layers. On the named volume, TREC-COVID throughput increased from 11.77 QPS to 38.45 QPS and indexing wall clock decreased from 8.42s to 7.10s.
3. **Dense Vector Acceleration**:
   - Shivvr embedding was executed against the local host GPU (`POST http://host.docker.internal:8085/embed`), achieving ~110 documents/sec for batch encoding. Luxir vector ingestion integrated dense cosine similarity vectors seamlessly into unified schema segments.

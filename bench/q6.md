# Native Q1–Q8 query-class benchmark

`ti-bench` normally opens a telemetry-only session. The `ti-query-bench` runner injects `LumeText`, the same lexical document implementation used by the server, so the six golden `q6-*` queries exercise text plus telemetry. The existing 20 selected queries remain unchanged; `--include-q6` adds all six Q6 cases.

Run in the w4 clone from a native Windows PowerShell with Rust 1.96.x and Python 3, with `.lanes/data/store-full` already present:

```powershell
rustfmt --edition 2021 crates/ti-bench/src/harness.rs crates/ti-query-bench/src/main.rs
py -3 bench/native_q6.py checks
# Commit the benchmark sources before measuring: the report records HEAD.
py -3 bench/native_q6.py build
py -3 bench/native_q6.py measure
py -3 bench/native_q6.py clean
```

The driver uses the shipped release profile, disables incremental compilation, limits build concurrency to two jobs, and stops its process tree if target approaches 8 GB. Build and check logs stay in `.test-tmp/native-q6`. It writes the complete reports, query fingerprints, command lines, and a Markdown summary to `bench/results/<date>-<source-sha>.json` and `.md`.

Cache off and 256 MiB cache on run sequentially, with seven warm iterations per query. Cold clears the sealed bitmap cache per query; it does not clear the OS page cache or reset the normal document index/query cache lifecycle. Class metrics are the maximum per-query metric, not pooled class percentiles. With seven samples, the measured p95 and p99 both equal the maximum sample. Q6 is judged against the 200 ms edge warm-p95 threshold. Native x64 host measurements do not establish Pi performance, and Q8 DuckDB parity remains pending without a DuckDB timing baseline.

# Pi 5 live ingest load run: M2 item 3 (2026-10-07)

**Result: PASS.** Spec/06 asks for ≥ 20,000 values/s sustained live ingest for 1 h on a Pi 5, at ≤ 25 % of one core and ≤ 400 MB RSS.

## Setup

- **Hardware:** Raspberry Pi 5, 8 GB, SD card, no active cooler, running the HaLOS Marine image. Signal K, InfluxDB and the production Lume plugin kept running on the same Pi and the same SD card throughout.
- **Binary:** `lume` at `6f94543`, native aarch64, thin LTO, 1 codegen unit, `strip=symbols`.
- **Feed:** `ti-bench sk-feed` on loopback, port 3030.
  - 21 vessels (1 self, 20 AIS) and 224 paths per vessel, in batches of 100.
  - Ramp: 20,000 values/s for 3,600 s, then 25k, 30k and 40k for 300 s each.
- **Ingest:** a separate `lume ti ingest --signalk ws://127.0.0.1:3030 --store /home/pi/load-store` with the default config.
- **Sampler:** `bench/pi_ingest_run.sh`, every 10 s for 4,500 s (451 samples).

- **Volume:** 100,433,000 values in 75 minutes.
- **Losses:**
  - `samples_rejected_blocked`, `apply_failures`, `samples_dropped_late`: 0.
  - `ingest_blocked`: never set.
- **Storage:** the store is 81 MB on disk (28.9 MB of shard files). The WAL ended at 222 KiB and was truncated on every flush.
- **Temperature:** 74.7–82.3 °C. The firmware reported soft-temperature-limit frequency capping (`0xe0008`); the run was not cooled.
- **Mean rate during the 20k hour:** slightly under 20,000 because sampling windows straddle flushes. The 10 s samples alternate between about 10k and 30k around each flush, and the counter totals match the feed.

## Bugs this gate found (all fixed before the passing run)

1. **`7ea727d`:** the retained-window memory cap charged every sample instead of every accumulator, which blocked a healthy 20k values/s stream.
2. **`80c7f7e` (D47):** every flush rewrote all 4,704 open field files, with two fsyncs each. That took about 140 s per flush on the SD card, and the reader stalled. Flushes now write only changed fields behind one `syncfs`.
3. **`50d8b15`:** staged flush files were held open until the sync, which hit EMFILE at the 1,024-descriptor limit. They are now closed once written.
4. **`6f94543`:** the 64-window cap counted healthy live windows. A 21-vessel fleet keeps about 126 open, so 1,000–1,400 samples per run were rejected. The cap now applies only while the sink is failing.
